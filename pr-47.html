Big picture

The bridge between the game and the network, tried out for real

We chose mGBA because its Lua 5.4 scripting has a native socket API. Before building the client on it, issue #8 asked for proof of the three things the client needs (a frame callback, memory reads, a non-blocking socket) and a single pinned mGBA version, since the API changes between versions.

This PR adds a throwaway script that plays the client's role and a tiny echo server that plays the relay's role. Neither is production code.

Pinned versionmGBA 0.10.5

Latest stable release (2025-03-09). Pinned in the README.

Only on mGBA's unreleased master. 0.10.5 has a text buffer in the scripting window only.

Blocking callsconnect()

The only blocking socket call, and it's about 2 s even when refused on Windows. Everything after it is non-blocking.

How it works

Everything happens a little bit per frame

Scripts run on the emulation thread: anything slow inside a callback slows the game. So the script never waits on reads or writes. Its frame callback counts frames, flushes pending sends and sends a ping every 300 frames. When there's no socket, it tries to reconnect. The wait between attempts starts at 300 frames and doubles up to 3600 frames (~60 s), because each attempt blocks the game.

Receiving is driven by mGBA itself: a connected socket gets its own per-frame select() poll with a zero timeout, which fires received or error. The script drains the data, splits it into lines, and keeps any trailing partial line for later.

Decisions in this PR

Four choices worth checking

Back off reconnects, because connect() blocks

nextRetry = frames + retryDelay
retryDelay = math.min(retryDelay * 2,
RETRY_MAX)
# 300 → 600 → … → 3600 frames
Why

Added after an independent review. On Windows, a refused connect to localhost blocks for about 2 s; we measured 2169 ms on Windows 11. Retrying every 5 s froze the game again and again while the server was down. Backoff turns that into a rare hitch. The real client needs the same.

Read memory at the base of mGBA's own domains

local domain = emu.memory[name]
local base = domain:base()
emu:read8(base) emu:read16(base) …
# for name in { "wram", "cart0" }
Why

AGENTS.md forbids address literals outside client/addresses.lua. Asking mGBA for the EWRAM and ROM bases at runtime proves the read API without inventing an address or touching game variables (those are #9 and #11).

mGBA globals are allowed in client/spike only

files["client/spike"] = {
read_globals = { "callbacks", "console",
"emu", "socket" },
}
Why

client/lib/ must stay pure so it can be tested in CI. The PR says the same script placed under client/lib/ still gets luacheck warnings, so the purity rule keeps being enforced.

"Readable, but the first read would block" counts as closed

if err ~= socket.ERRORS.AGAIN
or reads == 0 then
disconnect(err)
end
Why

After select() says "readable", a zero-byte recv means the peer closed. Reading the code suggests mGBA can report a stale error code on Windows. Without this check the script would loop on a dead socket. This comes from reading the code and hasn't been seen happen yet.
