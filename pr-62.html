How it works

Events update state before drawing

The optional onEvent(kind, data, nowMs) hook publishes connection status and validated inbound messages. It never publishes the outbound hello or join key. DEBUG controls console detail independently of that hook.

  1. Welcome replaces the peer snapshot and resets latency.
  2. Join / presence update identity and position. Replacement clears the old session's position.
  3. Leave / disconnect remove a row or clear all remote rows and latency.
  4. Frame update expires stale peers and renders changed text on the redraw schedule.

Map comparison uses both map group and map number. Rows are sorted by player ID; missing presence is shown as awaiting presence rather than invented coordinates.

Decisions

Keep the model portable

Consume events, not log strings

validated message → copied fields
Why

The panel stays correct when DEBUG is disabled. Tests run without emulator globals and arbitrary payload fields do not enter the retained player records.

Position each native row

setSize → clear → moveCursor → print
Why

The real mGBA test exposed unwanted wrapping when a multiline string was printed as a stream. Explicit row positions and buffer sizing fixed the visible output; the bridge adapter tests cover that contract.

Renew presence before expiry

renew every 10000 ms · expire after 30000 ms
Why

#20 explicitly requests expiry. Unchanged valid presence now renews through the existing send budget, so stationary players remain listed. Hidden tuples remain hidden after reset. Blocked sockets do not build a renewal backlog; the server and message format are unchanged.
