Big picture

A gate between accept and the handler

The review of #49 found that room capacity bounds authenticated players, but nothing bounded sockets still waiting for hello. Each one owned a descriptor and a handler goroutine for up to five seconds. Opening idle connections in a loop could exhaust descriptors.

This PR adds a semaphore to room.Server.Serve, between listener.Accept and the per-connection handler. Room capacity, message rates and the protocol are unchanged.

How it works

One slot per unauthenticated socket

s.pending is a buffered channel of capacity 16. After each accept, Serve tries a non-blocking send. If it succeeds, the connection gets a handler and a release function wrapped in sync.Once. If the channel is full, the socket is closed on the spot.

The handler calls release as soon as the join key matches. The goroutine also defers release, so every other exit (rejection, read error, hello timeout, shutdown) frees the slot too. Calling it twice is harmless.

Decisions in this PR

What was chosen, and why

Issue #50 left the cap value and the overload behavior open, to be chosen and documented. These are the choices.

Close over-cap sockets without an error

default:
// Over the cap: close at once, without
// reading or replying ...
conn.Close()
continue
Why

Protocol v1 has no "busy" code, and adding one would be a protocol change outside #50. Writing a reply would also spend a write deadline per flood connection. The client sees a plain disconnect and retries.

Free the slot at key match, not at join

s.reject(c, protocol.CodeBadKey)
return
}
authenticated()
Why

Once the key matches, the room-capacity check takes over. The cap stays purely about unauthenticated sockets, which is what the issue asked to bound.

A constant of 16, no CLI flag

const maxPendingHandshakes = 16
Why

That is about three times the room capacity, so a whole room can reconnect at once. The send queue and timeouts are already constants. Only address, key and capacity have flags, and a new flag needs a reason first.
