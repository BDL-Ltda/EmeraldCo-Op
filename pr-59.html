Big picture

The missing link between the game and the server

Milestone 0.1 reads the player state from memory (memory.lua, #11). The server relays presence between players (#14), and the pure framing module splits the byte stream into lines (#16). Issue #17 joins the three: bridge.lua passes each state to net.lua, which talks to the server over mGBA's socket API.

How it works

One connection, driven once per frame

bridge.lua calls client:update(ms) every frame with a clock built from the frame count. The client connects once a verified game is running and it knows the save's trainer ID and gender. After welcome it sends presence only when the tile, map, facing or visibility changes, and a ping every 5 s. Replies arrive through the socket's received event, which mGBA polls each frame, so nothing waits.

Under the hood

What happens when the connection goes wrong

Every failure ends in one of two places: retry in RETRY_INTERVAL_MS (5000), or stop until the script is reloaded. Pick a case to see what net.lua does. The values come from client/net.lua.

Decisions in this PR

Three choices beyond the issue's list

The issue sets the behavior (presence on change, ping every 5 s, retry every 5 s). These are the extras the PR adds, open to pushback.

Throttle presence to one per 2 frames

MIN_PRESENCE_INTERVAL_MS = 30,
-- one frame is about 16.7 ms → ~30/s
Why

The server closes a connection that sends more than 50 messages in one second (#14). Fast state changes could cross that; at most one presence every 30 ms stays well below it.

A pure client, driven by a fake socket

net.new(config, { connect, again,
log, logError })
Why

AGENTS.md wants testable modules free of emu, socket and callbacks. net.lua gets the socket and the clock from bridge.lua, so net_test.lua can cover partial sends, chunked receives and retries in CI.

Clock from the frame count

frames * 280896 * 1000 // 16777216
-- ms at ~59.73 fps; stops while paused
Why

Socket events are polled once per frame, so a finer clock would not measure latency better. It also never goes back, which the ping and retry timers need.
