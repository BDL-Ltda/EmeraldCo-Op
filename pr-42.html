Big picture

One new step at the end of the workflow

Three humans review code written partly by agents. A diff shows what changed but not why, or how it fits the system. The new step runs after a feat or fix PR is open and hands reviewers a picture of the change. Other PR types skip it: the page costs a lot of tokens and adds little when behavior doesn't change.

How it works

Two branches, one comment

The code goes to master through the PR as before. The page goes to a separate walkthroughs branch that shares no history with master and is never merged. The numbers match the sections of SKILL.md.

Under the hood

The diagram vocabulary

Every walkthrough draws with the same CSS classes from template.html, so pages look alike and readers learn the symbols once. Select one to see what it means.

Decisions in this PR

Three choices that shape every walkthrough

A separate, never-merged branch

$ git -C "$WT" checkout --orphan walkthroughs
# first run only; later runs reuse it
Why

GitHub comments can't render or attach HTML, and the page isn't code, so it shouldn't sit in the PR's diff or in master. A branch gives each page a stable URL that a comment can link to.

One self-contained file, no framework

<!-- inline CSS, JS and SVG -->
<!-- only Google Fonts is external -->
Why

AGENTS.md avoids new dependencies. A single file opens offline after download. A reveal.js slide deck was tried first and dropped: plain HTML with SVG gave better diagrams with less machinery.

Nothing invented

$ git diff --stat origin/master...HEAD
# numbers, hashes, output: copied, never retyped
Why

A pretty page with a made-up number teaches the wrong thing with confidence. The skill says to leave out anything the agent didn't run or read, in line with "never invent memory addresses".
