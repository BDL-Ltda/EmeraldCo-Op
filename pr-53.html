Big picture

A test player, not another server

Issue #15 asks for a simulated player using the existing internal/protocol. This PR replaces the fakeclient placeholder; it does not change the server, game memory or Lua runtime.

How it works

Authenticate before the simulation starts

The hello/welcome order comes from protocol #12. The client waits up to five seconds for welcome, then sends an initial presence. Movement, map switches and heartbeats share one serialized writer; cancellation closes the socket and joins the decoder.

Under the hood

Three patterns, independent clocks

Choose a pattern to inspect its behavior. These are synthetic coordinates from pattern.go, not memory addresses or measurements from a running ROM.

Decisions in this PR

Keep the simulator small and safe

Reuse the protocol, including validation

protocol.Encode(message)
protocol.NewDecoder(conn)
Why

Issue #15 explicitly requires the shared codec. A second JSON implementation could silently accept invalid fields or lose exact ping timestamps.

Do not expose the join key

FAKECLIENT_JOIN_KEY
static help · structured logs
Why

The key need not appear in shell arguments. Remote error text is redacted before quoting, unknown payloads are never printed, and decoder errors become safe diagnostics.

Leave headroom below the server limit

0 < steps-per-sec ≤ 40
+ heartbeat + periodic warp
Why

The #14 relay caps each connection at 50 messages per second. The simulator validates finite, representable timer intervals and leaves space for control messages.

Unit contracts and real processes
