The client refuses to run on the wrong ROM

client/bridge.lua becomes the client's entry point. Before anything touches game memory, it checks that the loaded ROM is the exact build addresses.lua was generated from. On any problem it logs a clear error and stops, and the game keeps running.

Big picture

One number links the build to the player's emulator

Every address in client/addresses.lua is only valid for the exact ROM build it came from. If a player loads a retail ROM, an old patch or a dev's local build, every address is wrong, and from 0.4 on, writing to them could corrupt the game.

mGBA 0.10.5 can give a script only one fingerprint of the loaded ROM: its CRC32. So symgen now writes that CRC32 next to the SHA1, and the bridge compares the two values at startup.

How it works

Four gates, in order, before any game memory

The bridge stops at the first failing gate with a message that says what to do. Nothing crashes, and the game keeps running. The ROM gate runs once when the script loads with a game running, and again on every start callback, so switching ROMs while the script is loaded is caught too.

Decisions in this PR

Three choices worth checking

Compare a CRC32, not the SHA1

crc := crc32.NewIEEE()
io.Copy(io.MultiWriter(hash, crc), rom)
# addresses.lua: romCrc32 = "453202b6"
Why

mGBA 0.10.5's only ROM hash for scripts is emu:checksum(), a CRC32 that mGBA computes once when the ROM loads. Hashing 16 MB with SHA1 in pure Lua would freeze startup. Issue #10 already allowed the cheaper identity. SHA1 stays in the file for humans.

Probe the folder before loading anything

local probe = io.open(DIR .. "bridge.lua", "rb")
if not probe then fail(...) return end
Why

Testing from this checkout (C:\Users\Usuário\…) showed that mGBA opens the script itself, but Lua's io.open, loadfile and require can't open non-ASCII paths on Windows. Without the probe, the player would be told config.lua is missing when it isn't. This affects every later client module.

loadfile for config, not require

local chunk, err = loadfile(DIR .. name)
if err:match("^cannot open") then ...
Why

A missing file must produce the friendly "copy the example" message, a syntax error must say so, and reloading the script after editing config.lua must read the new file. require would cache the module and give a generic search-path error.

How it was tested

Unit tests, CI-equivalent checks and four real emulator runs

Go vet and race tests pass, luacheck reports 0 warnings, and rerunning symgen on a clean build of the pinned ROM gives no diff. The pure ROM check has its own tests, which run with plain Lua 5.4 until #16 adds the shared runner:

$ lua5.4 client/tests/romcheck_test.lua
ok toHex pads and lowercases
ok matching CRC is verified
ok expected CRC is case-insensitive
ok different ROM is a mismatch with both hashes
ok missing romCrc32 asks to regenerate addresses.lua
ok malformed romCrc32 is rejected

all romcheck tests passed

In mGBA 0.10.5 on Windows 11 (agent-operated): the four gate outputs shown above were all produced through the real File → Load script dialog. 100 calls to emu:checksum() took under 1 ms in total, so startup has no freeze. The "other ROM" was a one-byte-modified copy of our build, not a retail ROM.
