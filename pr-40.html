Big picture

We can't ship the game, only a diff

The repo is public, so a .gba can never be committed or uploaded. Players already own Emerald, so we give them only the difference between their ROM and ours. Making that diff needs the retail ROM, which CI doesn't have, so a release is a local step on a maintainer's machine. This PR writes those steps down.

Decisions in this PR

Two steps that look optional, and why they aren't

Apply the patch before shipping it

$ flips --apply emerald-coop-vX.Y.bps emerald-us.gba /tmp/check.gba
$ sha1sum rom/pokeemerald_modern.gba /tmp/check.gba
# both hashes must match
Why

It takes seconds and catches the costly mistakes before a player does: a patch made against the wrong dump, a stale build, or an overwritten file. Without it, the first person to notice is a player whose hash doesn't match the notes.

Package the client with git archive

emerald-coop-vX.Y-client/client/
├── addresses.lua generated by symgen (#4)
├── bridge.lua entry point (#10)
├── lib/ pure modules (#16)
├── config.example.lua
├── README.md
└── config.lua
ignored by git, so never packaged
Why

Only committed files go in, so a maintainer's own config.lua with a real join key can't leak into a public release. It's the same commit as the ROM, so addresses.lua matches the patched build.

docs/installing.md

A wrong ROM gets stopped four times

The player guide puts a check before and after patching. Flips and, later, the client add two more. Each failure ends in a clear message, never a broken game.

The invariant

One commit, three files that must agree

Memory addresses in addresses.lua are only valid for the exact ROM they came from. That's why the guides insist on building, patching and packaging from the same commit, and on publishing the patch and the scripts together.

How it was tested

The commands were run, not just written

Flips was built from source and the guides' exact commands were run on 16 MiB dummy files. No ROMs were involved.

$ flips --create --bps a.bin b.bin p.bps
The patch was created successfully!
$ flips --apply p.bps a.bin out.bin && sha1sum b.bin out.bin
3b55d47809ce1720fb6b30ea8c54e95a0858b8b2 b.bin
3b55d47809ce1720fb6b30ea8c54e95a0858b8b2 out.bin
$ flips --apply p.bps wrong.bin out2.bin
This patch is not intended for this ROM. Expected checksum C269D90E, got 253764FB.
# exit 1, out2.bin not created

Also: go vet and go test -race pass, relative links resolve, no forbidden files or secrets. The two-dev manual run was waived because the PR is docs only.
