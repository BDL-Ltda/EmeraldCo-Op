Big picture

A recovery clue, not a transaction

Issue #29 deliberately keeps vanilla lockstep saving. A crash inside that window can lose or duplicate a Pokemon. Issue #79 adds evidence for manual diagnosis, not escrow, replay or proof of a successful save.

How it works

Capture before cleanup; write after unlocking

The membership lock decides which connection sent each offer. The second confirm completes an immutable pair before broadcasting can remove a slow recipient. Filesystem calls happen only after the lock is released.

Decisions in this PR

Keep the change small and explicit

Working-directory default

$ server -trade-log trade-log.jsonl
# Default is relative to the working directory.
Why

go run uses a temporary executable. A persistent log must not follow that temporary path. Existing files are never truncated or rotated.

Minimum pairing state

One offer per unordered pair of connected players; at most ten pairs in the five-player room. Same-side repeats replace, rather than complete, an offer.

Why

The server remains a broadcast relay, not a trade state machine. The wire has no trade ID: replaying both confirms after completion logs another pair.

A narrow synthetic test mode

fakeclient -trade-confirm PLAYER waits for the partner and sends one all-zero fixture.

Why

It makes the required two-client audit check deterministic without implementing the full trade partner from #84 or using actual saves.

Go vet and uncached race tests passed all seven packages in an isolated Go 1.27.2 container. Lua passed 221 tests; luacheck reported no warnings/errors. ARM compile-only assertions checked Pokemon sizes/offsets. No ROM code or generated addresses changed.

The smoke test launched the real server and two fakeclients with a throwaway environment key. Only these sanitized summaries are public:

PASS manual CLI: server + two fakeclients -> exactly one complete JSON line; no key/IP
PASS manual CLI: one-sided confirm + partner disconnect -> no audit line
PASS manual CLI: invalid log path -> server error; reciprocal relay and pongs continue

A regression test first reproduced a lost pair when the second broadcast dropped a full recipient queue; capturing before broadcast fixes it. Other tests cover all 24 species permutations, lifecycle cleanup, append/restart, bad storage and storage outside the room mutex.
