How it works

Identity comes from the connection

A can claim any valid playerId in a presence frame. The server overwrites it with A's authenticated ID, stores a copy of the state, and queues it only for the other players. A newcomer gets that stored state in welcome.

Decisions

Serialize state, isolate sockets

Room lock covers order

presence → store → enqueue
Why

Membership and snapshots share the lock, so welcome is queued first and contains a consistent state. Each queued frame is encoded before later updates can change it.

Drop the slow receiver

full outbox → close → leave
Why

This follows #14's required policy. Backpressure belongs to one client; it must never block the room. The queue stays open during shutdown to prevent send-on-closed-channel races.

Check the exact session

players[id] == connection
Why

A replaced reader can finish decoding an old frame. Checking the connection prevents that stale reader from changing its successor's presence or removing the new session.
