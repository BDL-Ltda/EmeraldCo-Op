Big picture

Same relay, new vocabulary

The v1.5 re-planning (#29) set three rules. Trade messages are broadcast, and each one names its target. Clients are trusted, so the server only checks message shape. The version goes to 2 with no negotiation. This PR covers the protocol layer only: the codec in internal/protocol, the relay in internal/room, client/lib/protocol.lua and fakeclient. Nothing in the ROM or the mailbox changes.

How it works

The flow the messages are built for

The order below is a contract between clients. The server enforces none of it: it doesn't check that an invite came before an accept, or that the target exists. A player who is waiting sends trade_available again when it sees a join, since the server doesn't remember it. The attendant UI (#82), the virtual link (#81) and the trade log (#79) build on these messages.

Under the hood

Seven messages, their fields and their rules

Pick a message. The example lines come from docs/protocol.md, and both the Go and Lua tests decode and re-encode every one of them. Every message except trade_available has playerId and targetId, each 1–16 characters of [a-zA-Z0-9_-].

Decisions in this PR

Choices the issue left open

Broadcast, trusted clients and the v2 bump were decided in the re-planning. The issue left the names and encodings to the implementer, so these choices are this PR's.

One relay path, chosen by an interface

case protocol.Relayed:
s.relay(c, msg)
// broadcast(msg.WithPlayerID(sender), except sender)
Why

Each trade type has a WithPlayerID method, so the server uses one code path for all seven instead of seven switch arms. Presence keeps its own path because the server stores it for welcome. Trade messages are not stored.

Bytes as lowercase hex

validateHex(TypeTradeLink, "data", m.Data, 0, MaxTradeLinkBytes)
// [0-9a-f], even length, min..max bytes
Why

It has a single spelling, so the docs examples re-encode byte for byte. It's trivial to produce in Lua with toHex, and it matches the hex format #79 plans for its log. The cost is 2× size versus about 1.33× for base64. That still fits: 1024 bytes is four of the game's 256-byte link blocks.

Availability is re-announced, not stored

join → waiting clients re-send trade_available:true
leave → receivers treat that player as false
Why

The issue keeps the server a plain relay with no trade state. Without a re-announce rule, a player who joins late would never see who is already waiting. The rule is in protocol.md for #82 to implement.
